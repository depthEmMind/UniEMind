# UniEMind
[English README](README.md)

UniEMind 是一个面向具身智能机器人的开源认知架构。

构建统一的机器人“心智”，使机器人能够**理解世界、理解自身、理解物体与任务**，然后推理出自己应该如何再物理世界中自主行动


机器人需要持续回答：

* 世界上有什么？
* 我在哪里？
* 我能做什么？
* 周围有哪些物体？
* 这些物体有什么属性？
* 物体可以如何被操作？
* 当前任务是什么？
* 下一步该做什么？
* 上一次动作成功了吗？
* 我对世界的理解应该如何更新？

# 🧠 核心思想

UniEMind 围绕 **统一具身心智（Unified Embodied Mind）** 构建。
希望把感知、世界模型、记忆、认知、规划、技能与机器人执行连接成统一的闭环系统。
机器人不应只知道如何执行动作，还应理解：

```text
                    ┌───────────────┐
                    │     世界      │
                    └───────┬───────┘
                            │
                           感知
                            ↓
                    ┌───────────────┐
                    │   世界模型    │
                    └───────┬───────┘
                            │
          ┌─────────────────┼─────────────────┐
          ↓                 ↓                 ↓
       自我模型           物体模型           任务模型
          │                 │                 │
          └─────────────────┼─────────────────┘
                            ↓
                           记忆
                            ↓
                           认知
                            ↓
                           规划
                            ↓
                           技能
                            ↓
                           执行
                            ↓
                           反馈
                            ↓
                        世界模型更新
```

从而形成持续的感知—认知—行动—学习闭环。

# 🚀 快速开始

建议使用本机 conda 环境 `UniEMind`：

```bash
git clone https://github.com/depthEmMind/UniEMind.git
cd UniEMind

conda activate UniEMind
python -m pip install -r requirements-dev.txt
python -m pip install -e .

python examples/foundation.py
python examples/mvp_cup.py
python examples/mvp_pour.py
python examples/perception_pipeline.py
pytest
```

依赖说明：

* `requirements.txt`：运行时依赖
* `requirements-dev.txt`：开发与测试依赖（包含运行时依赖）

Foundation 示例会加载与具体硬件无关的机器人画像，并通过进程内 `DataBus` 发布版本化的 `RobotState`。ROS 2 被刻意放在可替换的传输层与适配器接口之后。

MVP 示例在仿真中运行规格文档中的两条闭环：

1. 找到杯子 → 接近 → 抓取 → 验证
2. 导航到实验台 → 找杯子 → 抓取 → 移动到水槽 → 倒水 → 验证

# 🧑‍💻 开发理念

UniEMind 遵循若干长期工程原则。

### 1. 模块化

核心组件应有清晰接口与可替换实现。

### 2. 仿真优先

新能力应尽量先在仿真中验证，再部署到实体机器人。

### 3. 硬件无关

认知架构不应依赖某一特定机器人平台。

### 4. 框架无关

外部框架应通过适配器与接口替换。

### 5. 可测试

重要行为应有自动化测试与回归基准。

### 6. 可复现

实验应尽可能可复现。

### 7. 开放

在许可与安全允许的前提下，公开研究、实现、评测与文档。

### 8. 长期可维护

API 稳定性、文档、测试、代码质量与向后兼容都是一等事项。
